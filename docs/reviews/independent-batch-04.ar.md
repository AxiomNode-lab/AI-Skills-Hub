# المراجعة المستقلة — الدفعة 4: عشر مهارات Python من microsoft/skills

تاريخ المراجعة: 2026-10-03. هذه الدفعة الرابعة من المهارات الـ139 التي أعادها PR #11 إلى `review-required`. السجل الآلي الكامل في [independent-batch-04.json](independent-batch-04.json). الدفعات السابقة: [1](independent-batch-01.ar.md) و[2](independent-batch-02.ar.md) و[3](independent-batch-03.ar.md).

هذه مراجعة بمساعدة AI قرأت كل ملف كاملًا. ليست شهادة أمنية، ولا تقييم أداء، ولم يُشغَّل أي كود.

## ما المختلف في هذه الدفعة

- **كلها Python**: التخزين (Blob وData Lake وFile Share وQueue)، والمراقبة (Query وOpenTelemetry)، وTables وEvent Grid وKey Vault.
- كل مهارة فيها أمر `pip install` لحزم Microsoft رسمية بلا رقم إصدار. لذلك خطورتها **متوسطة**.
- **فحص جديد:** هل ما زالت الحزمة التي تثبّتها المهارة تحتوي الواجهات (APIs) التي تشرحها؟ رجعنا لسجل تغييرات SDK الرسمي، فوجدنا حالة واحدة.

## لماذا عُلّقت azure-monitor-query-py

- المهارة تثبّت `azure-monitor-query` **بدون رقم إصدار**، فيأتي أحدث إصدار، وهو 2.x.
- في الإصدار 2.0.0 (30 يوليو 2025) حذفت Microsoft `MetricsQueryClient` و`MetricsClient` من الحزمة، ونقلتهما إلى `azure-monitor-querymetrics` و`azure-mgmt-monitor`.
- الدليل: `Azure/azure-sdk-for-python`، الملف `sdk/monitor/azure-monitor-query/CHANGELOG.md`، قسم 2.0.0.
- **النتيجة:** قسم المقاييس (Metrics)، وهو نصف ما يعد به وصف المهارة، سيفشل عند أول استيراد.

قسم السجلات (Logs) ما زال صحيحًا. يمكن إعادة إصدار المهارة إذا حدّثها المصدر، أو إذا ثبّتت `azure-monitor-query<2`.

## تحديث قاعدة التعليق

| الحالة | القرار |
| --- | --- |
| الخدمة توقفت | تعليق: `upstream-service-retired` |
| الخدمة مغلقة أمام العملاء الجدد | تعليق: `upstream-service-retiring` |
| **الواجهة الأساسية حُذفت من الحزمة التي تثبّتها المهارة** | **تعليق: `upstream-api-removed`** |
| موعد إيقاف مستقبلي، أو أخطاء في أمثلة يمكن إصلاحها بسطر واحد | إصدار مع ملاحظة |

**لماذا أُصدرت File Share رغم أن مثال الدخول يفشل؟** الإصلاح معامل واحد (`token_intent="backup"`)، والخطأ يظهر فورًا برسالة واضحة. أما Monitor Query فلا يوجد إصلاح داخل نفس الحزمة.
